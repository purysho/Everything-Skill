# Security policy

The CLI starts offline. Search only projects eligible public records and applies known private blocks before display. Discovery sends the explicitly entered query to the selected public provider. Treat all source data as untrusted and never execute code, setup instructions, tools, or transports supplied by a source.

Online verification checks bounded metadata and selected public files. Findings are heuristic and use fixed, redacted categories. A credible credential, malware, fraud or uncontrolled capability signal is a sticky hard block. Stored reports are append-only through the supported database schema. Source verification is tied to a pinned revision. A newer revision requires review before inclusion in a released catalogue.

Private adapters are synthetic fixture previews. The contract runner starts fixed generated code under Node file and process restrictions with a reduced environment. It is not a sandbox for arbitrary third-party JavaScript. It does not implement live browsing, authenticated requests, credentials or state-changing operations.

Private data and telemetry stay local. Keep the index directory and backups user-owned. Windows uses the folder ACL. Only restore a backup you own and trust. Confirm writes and authenticated actions explicitly in host workflows. The application does not automate publication, purchases, messages or account changes.
